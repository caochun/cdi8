## 四类组件初始化口径（2026-10-15 用户确认）

本节及四类组件对应条目按用户确认更新，优先于早期转写稿中的“开机自检”及其候选状态映射。原 Excel 行号继续用于追溯；当前工作区未包含原 Excel 文件，本次修改的是这份 Markdown 转写稿。其他分系统的历史条目仍待逐项审核。

- **上电检查**：各系统检查自身所辖设备是否均已上电。只检查和反馈上电状态，不执行上电操作；连通、心跳及接口服务可用性由通信/服务健康检查处理，不替代上电反馈。
- **功能检查**：各系统测试所辖设备功能是否正常，具体测试项目及判据由对应分系统提供。总控接收检查结果并确认当前设备资格。
- 所需设备未全部上电或反馈未知时，上电检查不通过；功能未通过或结果未知时，不授予业务就绪资格。
- 四类组件均须先通过上电检查，再通过功能检查，才能接受参数下发。`ready` 表示已取得功能正常的基础业务资格；具体业务动作仍需检查有效参数及各自前置条件。

| 外层主状态 | 内层子状态 | 含义及下一步 |
|---|---|---|
| 未就绪 `notReady` | `unchecked` | 待上电检查；允许 `power_on_check` |
| 未就绪 `notReady` | `powerOnOk` | 所需设备均已上电，待 `function_check`；禁止参数下发 |
| 未就绪 `notReady` | `checkFailed` | 功能检查未通过；允许重新检查，禁止参数下发 |
| 就绪 `ready` | `functionReady` | 功能检查通过，业务就绪；允许参数下发 |
| 就绪 `ready` | `parameterOk` | 本次参数配置生效；按组件专有条件执行出光、唤醒或准直等动作 |

上电检查失败回到 `notReady/unchecked`；功能检查失败进入 `notReady/checkFailed`。失败原因和每次请求的 `accepted/succeeded/failed` 等任务状态独立记录，不新增“检查中”设备状态。功能检查失败后重试成功才恢复业务资格；关机或故障恢复后重新执行两项检查。

总控初始化流程采用两道整组屏障：**所有组件上电检查通过 → 所有组件功能检查通过 → 初始化完成**。各组件自身也执行资格检查，禁止绕过前置检查直接下发参数。

本次统一的模型版本为种子源 v3、二倍频 v2、预放 v2、多程 v2。旧模型数据库与命令记录保留，版本不兼容时拒绝复用；新模型使用独立持久化路径，不把旧自检成功记录解释为新业务资格。

## 状态分层定义

本文按层级状态机理解各分系统状态。状态分层描述包含关系，不描述状态的重要程度：“出光”本身就是重要的外层主状态。本文统一采用“外层主状态”和“内层子状态”；原表字段与真实父子状态之间需要逐项映射。

### 外层主状态（复合状态）

外层主状态表示分系统当前所处的持续工作阶段或总体资格，并作为一个可以包含内层子状态的复合状态。它回答“分系统现在处于哪个阶段、具备什么持续能力”，也是集中管控系统进行跨系统编排和流程放行时主要检查的状态。

以光纤种子源为例，外层主状态包括“未就绪”“就绪”“出光”和“设备异常”。“出光”本身就是一个状态，而不是对某个动作的简单描述；只要稳定供光条件保持，内部采集动作的进展不会改变外层主状态。

### 内层子状态

内层子状态描述某个外层主状态内部需要区分的局部条件。只有该条件影响后续事件响应、允许操作或结果判断时，才保留为子状态。例如“出光”内部包含“尚无本次采集结果”“采集完成”“采集失败”，内部变化不改变稳定供光的父状态。

不要求每个动作都有“等待—执行中—成功—失败”四种设备状态。请求、执行进度、超时和抢占由独立任务记录保存，不构成第三层设备状态。只有相关条件变化或有效反馈确认，才推动设备状态转换。

### 事件、反馈与状态转换

- **事件**是状态转换的触发因素，例如参数采集请求、采集成功反馈、设备故障确认、正常复位完成。
- **事件来源**可以是分系统内部（设备反馈、监测、计时器等），也可以是外部（总控请求、人工操作等）。来源不决定状态转换的层级。
- **同一复合状态内的子状态转换**只改变当前子状态，父状态保持。例如外部采集请求创建任务，状态可以保持“尚无本次采集结果”；收到完成反馈后进入“采集完成”，外层始终是“出光”。
- **跨主状态转换**退出当前复合状态。例如内部稳定出光确认使“就绪”转为“出光”，安全关机完成且反馈可信后，设备由“就绪”或“出光”转为“未就绪”。
- **反馈或判定条件**是事件携带的证据、守卫条件或分系统确认结果，不自动等同于新的外层主状态。
- **业务动作**是发出的请求或执行意图，不等同于状态；动作完成后，必须由分系统反馈和判定条件确认相应的状态转换。

### 与原表字段的对应

原 Excel 的“业务状态”主要提供**外层主状态候选值**；动作条目中的该值通常描述动作完成后的主状态，不表示执行期间一直处于该状态。原 Excel 的“关键状态”混合了反馈结果、持续条件和局部状态，不能机械地全部作为内层子状态。

种子源、二倍频、预放、多程的初始化映射已按本次用户确认统一；其余章节沿用的“内层子状态”字段仍为待审核候选值，不能据此认为父子映射已经完成。描述及判定条件可同时涉及外层持续条件和动作结果。修订记录及原始转录表保留源表字段名用于追溯。

#### 状态机补充说明

当前种子源采用单一层级可执行参考模型，只保留“未就绪”“就绪”“出光”“异常”四个复合状态，删除动作过渡区及按任务进度展开的执行中状态。关光、复位、关机、中止和恢复由独立任务记录跟踪；请求接受即阻断相关调度，设备状态按实际资格变化和有效反馈更新。

| 外层主状态 | 内层子状态 |
|---|---|
| 未就绪 | 状态未确认、上电检查通过待功能检查、业务资格未满足、关机正常 |
| 就绪 | 业务就绪完成、参数配置正常、复位/待机完成 |
| 出光 | 稳定出光正常、采集正常 |
| 异常 | 故障锁定、通信异常、执行超时 |

子状态只表达影响后续操作的局部条件。任务忙碌、执行失败原因、资源锁、数据有效性及完整故障集合独立保存，不能机械地全部变成设备状态。“采集完成”不等于数据有效；“就绪”也不等于允许立即出光，仍须有效参数、联锁、反馈及无冲突任务。

原表“稳定出光正常”“复位/待机完成”“关机正常”等在历史模型中作为结果证据。下列条目保留原 11 条编号与原表结果，另列历史转换；当前参考模型已将这些关键状态建为内部状态。状态图可在[模拟器 GUI](../../../simulator/README.md)中选择种子源查看。
