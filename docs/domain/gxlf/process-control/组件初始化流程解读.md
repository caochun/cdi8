# 四组件初始化流程

此流程演示操作流程与实验系统状态的协作。BPMN 按顺序组织四组件的上电检查和功能检查；独立系统状态模型声明“未初始化、已上电、已初始化”，并列出每个已达状态必须持续成立的设备谓词。

## 操作结构

1. 流程启动时由 `system_state_open` 载入 BPMN process 引用的 `gxlf-initialization` 声明，运行实例系统状态初始化为 `uninitialized`。
2. `normal` 子流程为种子源、二倍频、再生与双程放大、多程放大分别建立并行分支；每一分支使用多实例任务覆盖对应设备集合。先并行完成上电检查，汇合后进入功能检查。
3. `report_powered` 报告 `powerChecksVerified`。运行时读取 `allComponents` 的 Tango 快照，逐台验证目标状态的谓词，成功后才把系统状态改为 `powered` 并追加历史记录。
4. 每个功能检查命令在开始时要求系统仍为 `powered`，其余设备持续监测也会检查当前系统状态声明。四类功能检查汇合后，`report_initialized` 同样验证目标谓词并报告 `initialized`。
5. 命令失败、等待超时或系统状态完整性失效都走 BPMN 错误终止路径。流程失败不会推断设备已停止；未确认动作会保留在运行记录中。

## 系统声明

声明源文件位于 [`gxlf-initialization.system.xml`](../../system/gxlf-initialization.system.xml)：

| 状态 | 设备条件 |
|---|---|
| `uninitialized` | 初始化开始到四类上电检查汇合；种子源保持 `statusUnknown` 或已到 `powerOnChecked`，其他组件保持 `unchecked` 或已到 `powerOnOk` |
| `powered` | 每台种子源为 `powerOnChecked` 或外层 `ready`；其余三类设备分别满足各自上电检查状态或外层 `ready` |
| `initialized` | 种子源为 `qualified`，其他组件为 `functionReady` |

`allComponents` 是运行时从实际参与设备构造的集合。每个 `require` 针对集合中的所有指定组件实例；叶状态 `states` 和外层状态 `outerStates` 是“或”条件。若声明条件没有匹配到任何对应组件，系统状态无法被确认。

系统声明不是设备动作准入表。设备 SCXML 仍定义动作请求迁移、`cond` 守卫及本地忙闲互斥。BPMN 上的 `act:actionContract` 引用设备原生就绪结果，必要时 `act:entryCondition` 只能进一步收紧本次操作的进入条件。期望完成状态仍通过命令字段 `expectedState` 校验。

## 持续监控和异常

运行控制持续消费 Tango 事件，并以声明的 `evidenceMaxAgeMs` 控制快照刷新。如果观察到系统谓词瞬态不成立，即便设备在下一次轮询前已恢复，也会将 `experimentSystemState.integrity` 锁存为 `violated`。连接或事件证据不连续、实例 ID 更换、修订号倒退及快照无法确认会锁存 `unknown`。状态恢复不会清除本次运行记录的失败。

状态转换报告在目标谓词全部通过后才生效；BPMN 并行汇合本身不改变系统状态。后续操作可使用 `sys:requires state="powered"` 重新确认要求状态，并且真正下发动作前还会执行设备契约检查。

旧资格扩展 `ctl:qualification`、`ctl:accept`、`ctl:establish`、`ctl:require` 和 `qualificationPolicy` 已不再支持。迁移后，跨设备高层事实统一在系统状态声明中表达，操作 BPMN 通过 `sys:systemModel`、`sys:requires` 和 `sys:report` 与其协作。

系统状态模型解析和运行实现见 [SystemStateModel.java](../../../../server/src/main/java/cn/cdi8/workbench/systemstate/SystemStateModel.java) 与 [SystemStateRuntime.java](../../../../server/src/main/java/cn/cdi8/workbench/systemstate/SystemStateRuntime.java)；设备契约定义见 [实验过程约束](../../../architecture/process-constraints.md)。
