# 物理实验诊断系统集中控制软件——需求理解

## 系统定位

本系统是 GXLF 装置的"物理诊断大脑"，处于软件体系的中间层：

```
集中管控系统（总控）
    ↓ 下发任务/指令          ↑ 反馈状态/结果/健康度
物理实验诊断系统集中控制软件 ← 本系统
    ↓ Tango接口下发控制      ↑ 设备状态/采集数据
各诊断设备服务软件（示波器、相机、高压电源、DIM等）
```

服务两类用户：
- 诊断分系统值班长：统筹决策、参数配置、流程控制、任务确认
- 诊断设备运行人员：设备接入、离线测试、日常操作

## 业务流程（五阶段）

```
开机自检 → 功能检查 → 发射准备 → 正式发射 → 发射后处理
```

每个阶段由集中管控系统下发指令，本系统执行并反馈。

## 各模块需求要点

### 一、诊断数据管理（001-005）

核心是一个三层树形数据模型 + 横切逻辑分组：

```
诊断系统 (1 → N)
  └── 诊断设备 (1 → N)
        └── 诊断单元（最小控制粒度，直接对应 Tango 服务）

诊断分组（横切，按操作流程归类单元，用于批量控制）
  └── 诊断单元（多对多）
```

**诊断单元接入（001）**：最底层基础。每个单元对应一个物理仪器，接入时同步注册 Tango 服务（失败回滚）。不同设备类型有不同的预设参数和控制指令（多态）。权限隔离：谁创建谁管理，其他人只读。

单元数据字段：唯一标识、编号（自动生成）、名称、类型（CCD/示波器/高压电源/CMOS相机/分幅条纹相机）、厂商、型号、所属设备分组（树形）、所属系统（树形）、状态（运行中/正常/故障/告警/禁用）、Tango注册ID（自动生成）、通道数量、数据采集类型（波形/电源/图像/分幅相机/条纹相机/搭载平台/能量测量等基类）、注册时间、备注。

各设备类型的预设参数：
- CMOS相机：制冷温度、监控温度、曝光时间、门控时间、增益、触发模式（内触发/外触发）
- 示波器：触发模式、触发通道、时基、幅值、基线、带宽、耦合模式
- 分幅/条纹相机：高压设置值、开光状态、环境温度、环境湿度
- 高压电源：电流（设置/实际）、电压（设置/实际）、通道工作状态、极性
- 标定模块：激光器状态、制冷状态、出光状态、制冷温度
- 运动控制模块：当前位置、当前滤片位置、设备故障码
- 光电管高压电源：电流、电压、通道工作状态、极性、设备状态、高压输出状态、加高压速度

各设备类型的控制指令：
- CMOS相机：制冷、本底采集、采集、停止采集
- 示波器：通道选择、单次采集、停止采集、耦合
- 分幅/条纹相机：CCD开关、平压增益开关、同步触发复位、高压设置（阴极高压/屏压/扫描高压/像增强器高压）
- 高压电源：通道扫描、高压上电、高压下电、监控开启、关闭监控
- 标定模块：波长切换、横纵模式切换、重频设置、能量设置、触发模式设置、出光、停止出光
- 运动控制模块：设置转动速度、设置手动转/后转、设置零点、电机重置、电机上电、电机下电
- 光电管高压电源：通道扫描、高压上电、高压下电、监控开启、关闭监控

操作要求：新增时同步 Tango 注册（事务性，任一失败回滚）；支持预设参数配置；支持远程控制（调用单控界面）；支持查询设备已参与的实验任务；所有操作留痕。

**诊断设备管理（002）**：中间层聚合。一个设备由多个单元组成（如"全孔径背向散射测量模块"含门控相机2个+光谱仪1个+条纹相机1个+示波器2个+运动控制模块1个）。

设备数据字段：唯一标识（自动生成）、名称、运行状态、关联诊断单元（List，树形选择）、设备描述、创建人（自动）、创建时间（自动）。

操作要求：支持分配/移除诊断单元；删除设备时若有关联单元需提示确认后解除关联；权限隔离同上。

**诊断系统管理（003）**：最顶层聚合。一个系统包含多个设备。

系统数据字段：唯一标识（自动生成）、名称、系统负责人、运行状态、关联诊断设备（List，树形选择）、系统描述、创建人（自动）、创建时间（自动）。

操作要求：支持分配/移除诊断设备；删除系统时自动解除设备关联；权限隔离同上。

**诊断分组管理（004）**：将具有相同操作、同一处理流程的诊断单元划分为逻辑组，用于批量操作和统一配置。与设备/系统的物理层级关系不同，分组是按操作流程的横切组织。

分组数据字段：唯一标识（自动生成）、分组编号（自动生成）、名称、分组类型、关联诊断单元（List，树形选择）、分组描述、创建人（自动）、创建时间（自动）。

操作要求：支持分配/移除诊断单元；支持对分组内所有单元进行远程群控调试（通过设备指令批量操作）；支持分组启用/禁用状态管理；权限隔离同上。

**实验数据分析（005）**：面向诊断值班长的多维度数据对比分析功能。

数据分四大类：
- 关键过程数据：实验运行关键节点的设备基本属性数据（数值型）
- 原始测量数据：发射后设备采集数据——相机（图片）、示波器（二维数组+图片）、光谱仪（一维数组）
- 预处理数据：原始数据经设备厂商 Tango 服务处理后的结果（二维数组+图片）
- 仿真数据：来自第三方仿真系统，与真实数据结构一致

五种对比维度：
1. 多实验发次对比：不同发次间同一设备的关键参数差异分析
2. 实验与仿真对比：同一发次的实测数据 vs 仿真数据验证
3. 同类型单元对比：不同发次间同类型单元的数据对比
4. 分组单元对比：同一分组内多个不同单元的数据对比
5. 通道对比：同一设备不同通道间的数据一致性分析

四种分析算法：偏差分析（数值+百分比）、求平均分析、求异分析（自动标注差异项）、趋势分析（多发次参数趋势图）。

分析规则：数值型参数可做偏差/均值/极值/求异；采集结果（图片/波形）直接并排展示。各设备各参数支持的分析算法详见需求原文对比分析数据表。

### 二、诊断控制管理（006-011）——系统核心

**实验参数配置（006）**：

```
集中管控系统 ──下发──→ 实验任务（名称、发次编号、激光参数、靶参数等，只读）
                         ↓
诊断值班长 ──配置──→ 诊断参数（各设备工作参数，可编辑）
                         ↓
                    任务确认 ──上报──→ 集中管控系统
```

实验任务数据项（从总控获取，只读）：实验名称、发次编号、实验目的、参试设备、实验时间、靶型、靶号、装置要求、值班长。

激光参数（只读）：束线、总能量(J)、单束能量(J)、波长、脉冲延时(ns)、二倍频光谱(nm)、带宽(%)、波形、脉宽(ns)、峰值功率(TW)、束间能量不平衡度(%)。

靶参数（只读）：靶类型、靶编号、直径(μm)、弹着点坐标(μm)、离焦量(μm)。

诊断参数（可编辑，各设备类型不同）：同诊断单元接入中的预设参数。

两个使用时机：
- 计划阶段：打靶通知单提前发送后，诊断值班长提前配置（诊断单元选择、执行流程配方绑定、诊断参数调整）
- 任务阶段：发射流程运行前期针对实际情况预留参数配置入口；正常运行后只需计划阶段提前配置，实验任务接收后直接自动化执行预设流程

处理要求：修改任务信息（权限校验）、查询任务（按发次编号/状态/审核状态/时间组合查询）、参试设备配置（树形选择设备，展示厂商/编号/IP等详细信息）、查看原始数据/处理数据/设备状态、实验流程运行（可视化查看+运行控制）、实验任务确认（配置完成后上报总控）。

**流程编辑（007）**：可视化工作流设计器（类似 DAG 编辑器）。

流程配方数据项：流程名称、流程描述、关联实验任务（自动）、版本描述、配置人（自动）、配置时间（自动）。

设备控制节点数据项：节点名称、节点ID（自动）、设备分组（下拉，来源于分组管理）、设备列表（下拉，选分组后自动加载）、设备命令（下拉，选分组后自动加载对应指令）、设备参数（根据分组和指令动态配置）。

连接线数据项：连接线名称、连接线ID（自动）、条件表达式（支持基于数据状态/业务规则的复杂判断，实现并行/分支路径和安全联锁判断）。

操作流程：拖拽节点到画布→连线编排→配置节点参数和连线条件→保存→校核（完整性+合规性）→发布。未发布的可编辑/删除，发布后供调度执行调用。

典型的设备控制指令序列（实验阶段）：
```
DIM伸出 → 设备定位瞄准 → 设备参数配置 → 示波器接地 → 高压加载
→ 示波器采集参数配置 → 示波器DC耦合 → 读取设备状态
→ 数据采集（相机/示波器/光谱仪） → 相机(CCD)回温 → 相机(CCD)关机
→ 高压卸载 → DIM收回 → DIM下电
```

每个指令都有超时机制：要求一定时间内完成，故障时反馈给相应节点，由诊断值班长决定是否暂停流程并上报总控。

**流程执行控制（008）**：运行时引擎。

执行流程：选择已发布流程配方→加载流程步骤/关联任务/设备信息→启动自动化调度→通过 Tango 向设备服务下发控制指令→根据节点反馈自动流转。

六种控制操作：
- 启动：初始化设备、自检、加载参数，进入待命后触发流程执行
- 暂停：临时中断，保留所有运行参数与节点状态，设备待命
- 执行：按节点时序依次触发设备动作和数据采集
- 跳过：跳过非关键异常节点，直接进入下一节点
- 预设子流程：可复用的子流程模块（如设备校准、数据预处理），主流程中按需调用
- 设备取消：撤销已下达的控制指令，释放设备资源，不影响其他节点

关键机制：
- 安全联锁事件优先级最高，触发后流程暂停在当前节点，等人工确认后才能继续
- 故障信息结构化存储至故障库，供故障树建模引用
- 成功的故障处理方案存储至故障诊断规则库，作为未来参考模板
- 流程节点颜色标注：正常绿色、异常红色

**诊断设备控制（009）**：设备控制界面的低代码编辑器。

核心能力：在画布中绘制设备控制界面→控件绑定 Tango 服务属性（接入设备后自动获取）→布局和属性展示可编辑→生成单控界面（单个设备）和群控界面（一组设备）。

权限机制：
- 非实验阶段：设备负责人可直接通过控制界面操控设备，无需额外权限
- 实验阶段：设备由主流程自动控制，设备负责人需申请单控/群控权限，审批通过后方可手动操作

所有设备控制操作都有超时机制，实验阶段故障反馈给总控系统。日志记录所有单控/群控/系统控制操作。

**安全联锁（010）**：系统最高优先级，一旦触发立即暂停常规运行流程。

核心安全联锁设备：DIM搭载平台（碰撞防护）、闸板阀、真空机（真空度管控）。

输入信号：关联设备、关联输入信号（外部系统）、判断逻辑、重置命令、人工联锁信息、中止指令、设备核心参数。

真空度安全联锁规则：
1. DIM伸入/伸出前：与真空靶室分系统交互获取实时真空度，不达标则禁止DIM伸缩
2. DIM伸缩过程中：实时监测真空度，超出波动范围或不达标则立即中止DIM伸缩
3. 正常工作期间：真空度不达标则控制闸板阀关闭、真空机加大功率，直至达标
4. 闸板阀/真空机故障导致真空度无法满足：立即触发联锁，禁止所有相关设备运行

设备碰撞安全联锁规则：
1. 与靶瞄准定位系统实时交互，获取DIM搭载平台X/Y/Z轴实时坐标
2. 计算DIM与周边设备/靶室壁/其他运动部件的实际距离
3. 距离小于阈值→立即触发碰撞联锁，中止DIM所有移动
4. 位置信号异常（如定位丢失）→视为碰撞风险，触发联锁

设备互斥矩阵：
- DIM搭载平台移动中 → 禁止闸板阀开关、真空机启停
- 闸板阀开启/关闭期间 → 禁止DIM装置伸缩、DIM搭载平台移动
- 真空机启停过程中 → 禁止DIM装置伸缩

异常指令处理：检测到中止指令→立即终止联锁响应流程→记录执行时间/操作人/指令来源；中止指令失效则按正常联锁规则执行。

关键信号失效处理：真空度/DIM位置/急停信号失效→系统进入安全锁定状态→禁止所有关联设备运行→故障排除+信号恢复+人工重置后方可解除。

输出要求：告警信息同步显示在实验态势分析界面和流程控制界面；设备声光告警；流程中断在当前节点，禁止后续自动执行，需人工确认后才能继续；所有联锁事件自动记录（触发时间/原因/影响设备/处理过程/解除时间），支持查询导出。

**诊断实验报告（011）**：通过提取实验数据填充预设模板，生成结构化报告。

报告内容：实验基本信息（发次编号/目的/时间/靶型/靶号/装置要求/负责人/束线数）、参试设备信息、参试设备运行参数、原始测量数据（相机图片/示波器二维数组+图片/光谱仪一维数组）、预处理数据（Tango服务处理后的结果）、实验数据分析（如有同发次仿真对比则展示）。

输出格式：Word。经诊断值班长确认后发送给实验负责人。

### 三、诊断设备状态监测（012-018）

**显示方案编辑（012）**：大屏显示方案的低代码编辑器。

显示控件类型：文本、图片、视频、音频、表格、柱状图、折线图、饼图等常见控件，以及 CCD、示波器、频谱等传感器虚拟仪表组件。

控件属性可配置：主题、大小、数据源绑定、展示方式（饼图/折线/柱状图等）。

方案模板数据项：名称、ID（自动）、描述、配置数据、创建/修改时间（自动）、缩略图、状态（草稿/发布）、模板JSON串（自动）、空间布局坐标。

操作流程：在可视化编辑空间中拖拽控件→配置属性和数据源→支持对齐/缩放/图层调整→保存为模板→校验状态为"已发布"后→选择目标硬件大屏→下发渲染。

**状态监测显示（013）**：面向诊断值班长的设备监测数据看板。

查询条件：实验发次编号、发次时间、设备类型、设备工作状态（运行/待机/故障/告警/禁用）。

展示内容：
- 实时数据看板：以数字/图表/进度条展示设备基本信息（类型/厂商/型号/状态）和关键参数（如CMOS相机的制冷温度/监控温度/增益/曝光时间等）
- 设备状态拓扑图：图形化展示设备布局与连接关系，颜色编码（绿正常/黄预警/红异常），故障时自动高亮闪烁+弹出告警窗口
- 设备详情弹窗：在拓扑图上点击设备→展示详细信息、当前运行参数、历史曲线（折线图）、告警记录（列表）

**故障及告警显示（014）**：实时监测各类诊断设备故障信息。

故障三级告警：轻微（黄色）、严重（橙色）、紧急（红色）。

故障详情数据项（26项）：故障编号、名称、发生时间、现象、等级、位置、类型、报警触发方式（声音/弹窗）、报警记录时间、发次编号、初步原因分析、所属束组/子束、发生阶段、所属系统/分系统/组件、故障器件、异常参数(JSON)、责任人、跟踪人、严酷度类别、发生概率、应对措施、处理用时、处理时间、所属实验发次、影响范围、触发场景。

关键处理：
- 严重/紧急故障立即触发报警（声音+弹窗），同时通过公共故障接口实时上报总控
- 故障关联数据联动：根据故障时间和设备编号，提取故障前N分钟+后M分钟（可配置）的设备状态与监测数据，绘制趋势图
- 历史追溯查询：按故障时间/类型等条件筛选历史故障报警信息

**视频融合（015）**：靶场多摄像头实时视频 + 靶室虚拟3D场景拼接融合。

核心能力：
- 视频融合：实时采集靶场各区域摄像头画面→提取特征点（靶室轮廓/设备标识/固定参照物）→与虚拟场景（靶球3D模型/设备3D模型）特征匹配→拼接融合为一体化画面
- 多视角切换：支持多摄像头视角切换，同步更新虚拟场景视角，支持多画面分屏
- 靶球内部虚拟漫游：控制虚拟视角在靶球内部自由漫游，查看内部结构/设备模型/运动轨迹
- 设备位置获取与转换：实时读取DIM搭载平台位置（相对坐标）→转换为靶球内部绝对坐标；对接靶瞄系统获取靶瞄位置
- 碰撞预判与安全联锁联动：基于预设距离阈值实时计算DIM与靶球内壁/靶瞄/其他设备的距离→小于阈值则向安全联锁发送触发信号→融合画面高亮显示风险设备
- 设备运动轨迹模拟：动态模拟设备运动轨迹（当前红色/历史灰色），支持实时更新与历史回溯

异常处理：摄像头信号失效→标注故障位置+保留当前画面；位置信号失效→暂停位置显示和轨迹模拟+联动安全联锁；融合失败→切换纯监控画面模式+告警。

**实验态势分析（016）**：大屏集中展示实验全流程态势。

展示区域划分：实验任务区、实验流程区、设备信息区、参数监控区、视频融合区、采集信息区。

实验流程展示：以可视化流程图展示整个实验流程，节点颜色标注状态（运行中绿色/暂停黄色/完成蓝色/异常红色），状态变化实时更新+提示。

设备信息展示：分类展示设备名称/型号/运行状态（正常绿/异常红/待机灰），关键参数按设备类型分类展示，参数超出正常范围自动标记异常+告警。

采集信息展示：诊断设备采集的信号以波形/图片形式展示，支持放大缩小。

集成视频融合功能的全部展示内容。

**VR展示——维修态势（017）**：

核心能力：在VR场景中以3D模型展示故障类诊断设备→根据故障数据自动定位故障位置并高亮标注→支持模型虚拟拆分/组装→在故障设备旁显示故障类型/位置/等级/时间→从故障诊断规则库筛选维修建议方案（方案内容/维修工具/关联故障/责任分配）。

**VR展示——VR培训（018）**：

核心能力：诊断值班长识别常规/典型的维修和实验流程→结合诊断设备3D模型生成三维动画→培训过程中展示步骤列表，支持切换步骤加载对应动画。

培训数据项：培训名称、类型、关联实验/维修流程、诊断设备、培训内容/目的、参与人员、上传文件、创建人/时间。

支持培训流程的增删改查、培训记录查看、培训材料下载。

### 四、诊断智能运维（019-023）

**健康评估管理（019）**：采用健康度加权求和算法，构建面向各类设备的通用健康评价指标体系（100分制），以实验发次为单位评分。

健康评价指标数据项：指标项、指标类型、指标占比、基础分、诊断项、扣分规则、扣分、扣分说明、备注。指标可自定义配置和维护。

评估流程：根据参试设备→依据健康评价规则和设备系统权重→加权求和算法→计算系统级/设备级健康评分和健康度→健康等级（A/B/C/D/E）→系统级整体健康度上报总控。

查询支持：按发次编号/健康等级/实验时间组合查询→系统级评分明细（各类设备评分列表+健康等级分布图表）→设备级评分明细（评分项/基础分/扣分说明/最终得分）。

**故障库管理（020）**：统一采集和维护诊断设备全生命周期故障基础信息。

两种故障来源：设备故障上报接口自动采集 + 设备运行人员人工录入。

故障基本信息数据项（29项）：故障编号（自动）、名称、发生时间、现象、等级、位置、类型、报警触发方式、报警记录时间、发次编号、初步原因分析、所属束组/子束、发生阶段、所属分系统/组件、设备/部件编号、异常参数(JSON)、责任人、跟踪人、严酷度类别、发生概率、应对措施、处理用时、处理时间、所属实验发次、影响范围、触发场景、累计实验发次数（自动）、投入使用时间、故障是否重复发生（自动）。

关键能力：通过记录故障发生时间/累计次数/关联发次/运行时长，自动统计部件基础故障概率。为故障树建模提供标准化节点数据。支持故障处理状态跟踪（处理/无需处理），对"处理"的故障支持维护任务创建与跟踪。

**故障树建模（021）**：以故障库标准化数据为基础，构建设备故障因果逻辑树。

模型结构：自上而下拆解——顶事件→中间事件→底事件，清晰呈现故障传导路径。

模型基础信息：故障树编码、故障名称、故障层级、故障描述、层级与关联关系、逻辑门关系（与门/或门）、关联设备/器件、关联故障节点、适用范围、建模时间、模型版本。

计算参数：统计周期、故障等级、事件发生概率、重要度阈值、预警阈值。

计算逻辑：底层事件基础故障率通过故障库中故障累计次数与总实验发次（或运行时长）统计得到→上层事件故障率根据下层事件故障率结合与门/或门逻辑或权重加权计算→逐级向上推导得到系统顶层故障概率。

预警机制：当事件发生概率 ≥ 预设预警阈值时，立即触发风险预警。

展示形式：可视化树形拓扑图为主、层级列表为辅，支持节点展开/折叠、缩放拖拽、风险颜色高亮，右侧信息面板展示节点故障信息/概率权重/预测结论。

操作流程：查询→故障建模（图形化维护层级/关联/逻辑门）→节点信息配置→校核→发布→计算→预警。

**设备寿命预测（022）**：以历史故障特征和数据为基础，结合健康度评估和故障树建模结果，使用各类设备寿命预测模型。

预测模型输入数据（五类）：设备历史维修记录、历史故障记录、设备运行参数、设备基础属性数据、实验计划数据（从总控获取未来一周/一月/一季度的实验排程）。

预测输出：关键部件当前健康度、预计剩余寿命、推荐更换时间窗口、可能的故障原因、影响范围评估。

关键能力：当关键部件寿命临近时自动提升设备整体风险等级；预测结果自动更新设备健康评估等级和故障风险概率；支持导出性能预测分析报告。

**智能运维（023）**：本地化 RAG 知识库 + AI 智能问答助手。

三类知识库：设备基础信息库（型号参数/运行阈值/历史故障）、故障诊断规则库（排查手册/维修经验/处理案例）、实验流程关联库（设备协同要求/参数联动关系）。

知识库构建流程：上传多格式文档（DOC/DOCX/EXCEL/PPT/IMAGE/PDF/TXT/MD/JSON/EML/HTML）→文档解析（OCR图片识别/文档布局分析/表结构识别）→文本切片（基于Token上限/重叠数/分段标识符）→向量化（本地嵌入模型）→索引构建（向量索引+全文索引）。

知识库配置项：名称、描述、语言、权限、嵌入模型、解析方法、自动关键词、块Token数、分段标识符。

检索配置项：相似度阈值、关键字相似度权重、多轮对话优化、Rerank模型。

智能问答流程：用户自然语言输入→查询预处理→向量数据库检索（相似度阈值+关键字权重）→命中重排序（Rerank剔除干扰项）→LLM结合系统提示词和检索上下文生成回答→返回答案+引用原文来源→支持多轮追问。

智能问答配置项：助理姓名、描述、系统提示词、空回复、开场白、显示引文、关联知识库。

### 五、离线测试（024-025）

**单元测试（024）**：对单个设备的离线调试，验证设备控制指令、采集参数及数据读取的正确性。

测试用例类型：波形采集单元、图像采集单元、电源、分幅相机、条纹相机、诊断搭载平台等。

操作流程：选择已接入的诊断设备单元→依据设备类型调用 Tango 服务接口加载设备属性和控制指令→灵活配置测试项形成可执行测试用例→输入测试参数→启动测试→执行设备控制指令（调用 Tango 接口验证接口调用状态/返回值/数据读取）。

控制操作：启动、执行、停止、继续、重置（恢复初始状态）。

测试输出两类结果：
- 参数类：根据输入目标参数输出设备对应属性值（如高压电源的电压和电流）
- 采集类：设备反馈的采集数据（示波器：波形二维数组；光谱仪：一维数据；相机：图像tif格式）

关键要求：单元测试数据与实验流程数据分开保存，互不影响。展示失败项和执行日志。支持生成单元测试报告（基于用户模板或系统内置模板）。

**虚拟实验流程测试（025）**：完整流程的仿真运行，实现虚拟实验流程仿真及全链路逻辑校验。

各类设备虚拟程序：波形采集单元、图像采集单元、分幅相机、条纹相机、诊断搭载平台、能量测量分系统、各种诊断包分系统。

操作流程：查询虚拟实验流程→新增流程（录入基础信息+拖拽节点编排）→流程自定义校验（通过则自动部署到仿真工作流引擎，不通过则弹出错误）→启动流程调试→在节点中输入仿真参数→执行流程流转（遇到表达式判断或需要输入参数时暂停）。

控制操作：启动、执行、停止（暂停，可查看已执行节点状态）、继续、跳过（跳到下一节点）、重置（恢复初始状态）。

与正式流程执行控制的界面和操作几乎相同，但走仿真工作流引擎。流程节点颜色标注：正常绿色、异常红色。异常时展示人工干预选项（修改仿真参数/暂停/跳过/继续）。

关键要求：虚拟实验流程测试数据与实验流程数据分开保存，互不影响。支持生成虚拟实验流程测试报告。

### 六、系统管理（026-028）

**资源管理（026）**：通过"组织机构→用户→角色→权限"四级架构实现全链路安全防护。

三类管理角色：
- 系统管理员：日常维护、注册与权限配置
- 授权管理员：对关键操作授权、账户与权限配置的审核生效（双人作业机制）
- 安全审计员：对管理员操作行为进行综合审计分析

权限管控：功能菜单访问权限（配置组/角色/用户的菜单可见性与操作权限）+ 数据访问权限（配置不同角色/用户对业务数据的可见范围与过滤规则）。

审计管理：记录操作人/时间/内容/结果，支持访问记录查询、操作日志导出与审计报告生成。

**接口管理（027）**：对系统中所有 Tango 设备服务接口进行集中管控。

接口总览仪表盘：接口总数、在线数量、调用成功次数/错误次数、在线率、成功率、错误率（图表+数字），支持定时/手动刷新。

接口状态同步：展示所有注册 Tango 设备服务接口的最新状态（已启用/维护中/已停用），按模块或设备类型分类。

权限分配：为不同角色/用户组配置 Tango 接口访问权限，支持批量授权，配置立即生效。

调用历史：自动保留所有调用记录（调用者IP/时间/耗时/状态码/入参摘要），支持导出 Excel。

依赖关系图谱：解析各 Tango 接口间的调用关系，可视化图谱展示，支持缩放/节点查看。

**日志管理（028）**：标准化日志体系，全流程行为留痕。

日志数据结构：时间戳(Long)、日志等级(String)、日志源(String)、日志信息(String)、线程ID(String)、详细描述(String)。

日志五级：DEBUG（调试信息）、INFO（操作提示/记录）、WARN（警告）、ERROR（一般错误）、FATAL（致命错误，程序可能关闭）。不同级别不同颜色区分。

日志分类：设备服务、外部系统服务、流程、操作、审计。

日志配置：可视化配置入口，自定义日志级别/文件大小/保留期限，配置即时生效。

日志接口：对外提供统一日志记录功能接口，完成权限校验后响应外部子系统的日志记录请求，实现跨系统日志统一归集。

日志清理与归档：定期自动清理超期/冗余日志，按周期归档有留存价值的日志。

日志监控与分析：实时监控异常/错误类日志触发告警；支持离线分析（按时间/级别/类型/模块维度）。

日志安全：精细化权限管控（查看/修改/删除权限分离）；防篡改/防删除技术手段保障数据完整可信。

| 健康度反馈 | 本系统→总控 | 系统/组件标识、束线、系统健康度(%)、关键设备名称/编号/健康度(%) | 接收状态 | 订阅模式(healthState/healthStatus属性) |
| 参数配置 | 总控→本系统 | 任务编号、发次编号 | 接收状态 | 根据发次/阶段/束线从总控参数配置表获取参数 |
| 发射控制 | 总控→本系统 | 任务编号、发次编号、阶段编号、指令标识(0准备/1数据采集/2流程结束/3流程中止) | 接收状态 | 发射三阶段任务下达 |
| 服务标识同步 | 总控DB→本系统 | - | 全装置服务标识列表 | 每日首次登录后读取一次 |
| 诊断设备状态确认 | 总控→本系统 | 任务标识、查询指令、对象标识、范围、时间 | 执行结果状态/说明/动作结果/错误码/原因/完成时间 | 确认诊断设备状态 |
| 诊断设备参数设置 | 总控→本系统 | 任务标识、采集指令、对象标识、参数、时间范围 | 执行结果状态/说明/采集结果/上传状态/错误码 | 完成数据采集存储和预处理 |
| 发射后处理 | 总控→本系统 | 任务标识、动作列表、动作类型(退高压/收回/下电等)、对象标识、参数 | 执行结果状态/说明/各动作结果/错误码 | 发射后保护动作 |

关键机制：
- 装置运行阶段编号：调试(TS)/维护(WH)/实验(SY)，每种含发射准备(A)/发射(B)/后处理(C)三阶段
- 发次编号格式：`类型编号+年月日+4位序号`（如 SY20260205XXXX），由运维任务管控组件下发
- 服务权限验证贯穿所有控制类接口，状态类/数据类接口无须验证
- 任务完成后权限默认收归运维任务管控组件

## 数据库需求

数据库分为公共库和系统库：
- 公共库：全系统共用基础数据（系统定义/组件定义/设备定义/束组定义/实验定义），装置管控软件读写，系统控制软件只读
- 系统库：各系统的实验参数和实验数据，本系统读写自己的库，对其他分系统库只读，装置管控软件对所有系统库只读

数据存储规范：标量数据存数值类型；必须加中文注释；UTF8字符集；禁止数据库内运算；禁止TEXT/BLOB类型（大文件存文件服务器，数据库存URL）；字符串用VARCHAR，明确长度用CHAR。

实验数据存储原则：仅保留原始数据及标准化后的结果数据，避免冗余。处理后的图片类数据不做永久保存，需要时"现用现调"。

数据库表命名规范：
- 系统库：`[分系统编码]_DB`
- 基表：`T_[分系统编码]_基表类型_自定义名`（基表类型：CFG配置/SYS公共/PARA参数/DATA数据）
- 存储过程：`P_[分系统编码]_自定义名`
- 视图：`V_[分系统编码]_自定义名`
- 触发器：`TR_[分系统编码]_自定义名_触发器类型`（I/D/U）
- 索引：`IDX_[分系统编码]_自定义名`
- 临时表：`TMP_[分系统编码]_自定义名`

## 需求关键特征

1. **Tango 是核心中间件**——所有设备交互走 Tango 接口，设备接入时自动注册 Tango 服务
2. **三个低代码编辑器**——流程编辑器（DAG工作流）、设备控制界面编辑器、大屏显示方案编辑器
3. **安全联锁最高优先级**——贯穿流程执行、视频融合、态势分析，触发后一切暂停等人工确认
4. **全链路日志**——几乎每个功能都要求操作留痕
5. **数据隔离**——离线测试数据 vs 实验数据严格分开；用户权限隔离（谁创建谁管理）
6. **与总控的双向接口**——上行反馈状态/健康度/故障，下行接收任务/指令
7. **发次编号贯穿全系统**——格式 `类型编号+年月日+4位序号`（如 SY20260205XXXX），是数据组织的核心索引
