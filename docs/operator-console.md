# Python 对照操作台与日志回放

当前主操作台由根目录 Spring Boot 提供，访问 8080。本文件描述保留在 simulator 中的旧对照操作台（8765）。
从根目录执行 make 命令；直接使用 python 模块命令前先安装 `./simulator`。

运行入口：

```bash
make legacy-operator
# 或指定日志文件、端口
python3 -m gxlf_sim_system.operator_server --port 8765 --log simulator/gxlf_sim_system/output/session.jsonl
```

访问 `http://127.0.0.1:8765`。默认每次启动生成独立 JSONL 文件。指定已有文件时保留原记录、追加新实验；
不会从日志恢复执行未完成的任务。日志损坏时拒绝加载并指出行号，不静默丢弃尾部内容。

当前正常流程有 14 个动作节点和 1 个联合门禁，覆盖双方自检、检查、参数下发、出光、采集、正常复位及关机。
“实验成功”表示四个仿真实例均已完成关机；“采集成功”不等于已退出出光。
更新模型后，已运行的实验仍使用其创建时的节点列表，需新建仿真实验或重启服务加载新流程。

## 操作顺序

1. “启动 / 下发下一节点”调用联合流程调度器。种子源节点同时产生三个活动任务，二倍频节点只有一个任务。
2. 在实例卡片上提交“模拟成功”“模拟失败”或“通信故障”。全部目标成功后才可调度下一节点。
3. “触发联锁”结束流程并标记待补偿；“模拟安全条件满足并执行补偿”显式提供演示证据并执行补偿。
4. 成功或失败后可“新建仿真实验”。有待执行补偿时禁止新建。新实验创建新的仿真实例，不向真实设备发出复位命令。

服务端每 200 ms 检查一次截止时间；浏览器每秒读取状态。浏览器关闭也不暂停超时检查。
处理命令前先检查超时，因此过期成功反馈不能因 UI 未刷新而绕过截止时间。
所有控制调用与时钟检查使用同一个会话锁，避免多个浏览器或重复点击同时改写流程。

## 事件格式与回放

JSONL 每行包含 `version=1`、连续 `seq`、UTC `timestamp`、`run_id` 和 `kind`。

| kind | 内容 |
|---|---|
| command | 原始控制请求、command_id、本地操作员身份 |
| transition | 节点、实例、action、task_id、转移前后快照、结果与原因 |
| checkpoint | 完整流程及实例快照、命令结果、模型文件 SHA-256 |

每次操作后收集状态机历史新增项，连同操作失败时发生的部分状态变化一并记录，再追加完整快照。
transition 的时间是收集时间；并行实例之间的写入顺序不是物理执行的先后顺序，单实例内部历史顺序保持不变。
这是一份仿真审计与回放日志，不是测量设备时延的工具。

回放滑块以完整 checkpoint 为单位，支持逐步、自动播放、返回实时，以及按运行/节点/实例/文本过滤。
回放期间禁用控制按钮；回放不会重新下发命令或修改实时实例。实时服务仍继续检查超时。
导入 JSONL 在浏览器本地完成，最多 20 MB；导出保留当前会话文件全部事件。
服务端 `Journal.replay(seq)` 返回该事件位置之前最近一个 checkpoint 的状态。

## 本地接口

| 路径 | 用途 |
|---|---|
| GET / | 操作台 |
| GET /api/session | 当前快照及事件列表 |
| GET /api/replay?seq=N | 只读回放快照 |
| GET /api/log | 原始 JSONL 下载 |
| POST /api/commands | dispatch / success / failure / fault / interlock / compensate / new_run |

命令要求 `command_id` 和 `run_id`；反馈还要求匹配的 target、task_id。
相同 command_id 和相同请求在当前进程中只执行一次；复用 ID 修改请求被拒绝。
请求被拒绝时仍保留审计结果。幂等缓存仅在当前进程有效，不承诺跨重启投递去重。

服务仅监听 loopback，POST 要求页面提供的随机 token，并校验 Host；这是单机仿真边界，
不提供多用户认证、分级授权或真实设备控制权限。接口错误明确返回，UI 显示待处理原因。

## 范围与后续

本操作台以“seed 三实例 fan-out + shg 单实例”作为完整演示入口，复用已有状态机和流程接口。
早期单系统、双单实例和独立 fan-out 示例已移除，命令行默认入口与操作台使用同一完整流程模型。
成功/补偿证据明确来自 `simulation.py`；UI 没有提供任意改写状态的接口。

目前日志同时保留在内存及 JSONL 文件中，适用于小规模本地实验；尚无分页、日志轮转、数据库持久化、
进程崩溃后的任务恢复或事件级精确时间重放。以上是后续工程增强，不应混同于本阶段的模型正确性证明。

验证涵盖：日志重建与实时快照一致、事件与实例历史逐条一致、旧反馈拒绝、命令去重、并发点击、
超时、联锁补偿、部分补偿失败、历史只读、文件损坏、HTTP token 检查。
浏览器验收覆盖实际点击、导入回放、实时切换和窄屏显示。
