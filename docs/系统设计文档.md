## 1. 背景与需求

### 1.1 系统定位

GXLF（高功率激光聚变装置）集中管控系统（JZGK）是连接物理实验操作层与各子系统设备层的中间控制软件。它统一编排从发次准备到发射后数据采集的全流程，实现：

- 多子系统并发初始化与状态核查
- 安全联锁信号的实时响应与中止补偿
- 发次数据的完整记录与模型校准驱动

实际系统使用 Tango 中间件与硬件通信；本项目以纯 asyncio Python 实现所有子系统的仿真模拟器，使控制逻辑可在无硬件环境中完整验证。

### 1.2 核心需求

| 需求 | 描述 |
|------|------|
| 发次流程管控 | 按 A（准备）→ B（发射）→ C（后处理）三阶段顺序执行 |
| 并发子系统调度 | A/B 阶段多个子系统可并发初始化，缩短发次周期 |
| 安全联锁 | S1（人员入侵）、S2（泵浦紧急停充）在任意时刻立即中止发次 |
| 故障分级 | 硬故障（光链/能源/真空）→ 中止；软故障（诊断/测量）→ 警告继续 |
| 中止补偿 | 中止后将所有已激活子系统带回安全状态 |
| 可观测性 | 每步耗时、发次测量数据、模型校准结果完整记录 |

### 1.3 关键设计挑战

在设计过程中识别出四个核心挑战：

1. **状态机建模**：控制器有明确的状态转换（IDLE→PREPARING→FIRING→POST），需形式化约束非法转换
2. **时间尺度分离**：模拟器内部时序（ns 级）与控制器等待（秒级）共存，通过 `sim_speed` 比例因子统一
3. **安全作为一等公民**：S1/S2 信号必须能在任意 await 点打断当前操作
4. **部分失败处理**：并发 gather 中某子系统故障不应阻塞补偿动作

## 3. 子系统模拟器

### 3.1 基类设计（BaseSimulator）

所有模拟器继承 `BaseSimulator`，共享以下基础能力：

```python
class SimState(enum.Enum):
    OFF      = "OFF"
    STANDBY  = "STANDBY"
    RUNNING  = "RUNNING"
    READY    = "READY"
    FAULT    = "FAULT"
```

| 方法 | 描述 |
|------|------|
| `_transition(state, msg)` | 状态转换 + 广播事件 |
| `_delay(seconds)` | 仿真延迟（实际耗时 = seconds / sim_speed） |
| `_emit_safety(signal_id, msg)` | 发出安全信号（S1/S2/S3） |
| `inject_fault(reason)` | 外部注入故障，用于测试 |
| `reset()` | FAULT → STANDBY |
| `is_fault` / `is_ready` | 状态查询属性 |

**子系统状态枚举设计**：Python 不允许继承带成员的 enum，因此各子系统定义独立的状态枚举，基类 `_state` 类型为 `enum.Enum`，用 `.value` 比较跨枚举状态。

**仿真速度**：所有 `_delay()` 调用自动除以 `sim_speed`，可将数十秒的模拟过程压缩到毫秒级完成测试。

### 3.2 子系统一览

#### 激光链路

| 子系统 | 缩写 | 全称 | 阶段 | 主要职责 |
|--------|------|------|------|----------|
| 种子源 | ZZY | 光纤种子源 | A | 产生激光种子，`enable_output()` / `disable_output()` |
| 注入 | EPJ | 二倍频宽带注入 | A | 倍频后注入放大链，接口同 ZZY |
| 预放 | YF | 再生与双程放大 | A/B/C | 唤醒（`wake_up`）、接收泵浦能量（`receive_pump_energy`）、接受吹扫（`accept_purge`） |
| 主放 | DCF | 多程放大 | A/B | 迭代准直（`align`，5 步收敛至 10 μrad）、接收泵浦并发射（`receive_pump_and_fire`） |
| 频转 | PLZ | 频率转换 | B | 晶体调姿（`set_crystal_pose`）、接收基频光输出紫外（`receive_fundamental`） |

DCF 准直仿真：5 步迭代，每步误差以 5 μrad 为基准加随机噪声，收敛阈值 10 μrad：

```python
for step in range(5):
    await self._delay(0.5)
    error = abs(5.0 + random.gauss(0, 3.0))
    if error < 10.0:   # 收敛
        break
```

#### 能源与时序

| 子系统 | 缩写 | 全称 | 主要职责 |
|--------|------|------|----------|
| 泵浦 | BB | 泵浦分系统 | 充电（10 步，每步 0.2% 故障概率）、触发放电、发出 S2 |
| 开关 | KG | 开关驱动源 | 充至目标电压（8 kV）、触发脉冲 |
| 同步 | JZT | 集中同步 | 加载配方时序、arm → fire 广播纳秒级触发 |

BB 充电故障模型：

```python
for step in range(10):
    await self._delay(0.5)
    self._charge_progress = (step + 1) / 10
    if random.random() < 0.002:   # 0.2% 每步 ≈ 2% 每发次
        await self._emit_safety("S2", "充电故障")
        await self._transition(SimState.FAULT, ...)
        return
```

#### 靶场与诊断

| 子系统 | 缩写 | 全称 | 主要职责 |
|--------|------|------|----------|
| 靶瞄 | BM | 靶瞄准定位 | 预定位（`pre_position`），仿真 XYZ 移动 |
| 真空 | ZK | 真空靶室 | 抽真空（40 步指数衰减）、后台监控漏气（S3）|
| 测量 | CLY | 测量取样 | 配置采样，发次后返回激光参数字典 |
| 诊断 | WLZD | 物理实验诊断 | 配置探测器，发次后返回 X-ray/中子/γ 信号 |
| 安全 | AQ | 安全联锁 | 清场→锁定→联锁激活，发出 S1 |

#### 支持系统

| 子系统 | 缩写 | 全称 | 主要职责 |
|--------|------|------|----------|
| 靶 | LDB | 液氘靶分系统 | 靶丸冷却准备与送靶 |
| 吹扫 | LK | 冷空系统 | C 阶段对预放片进行冷气吹扫 |
| 模型 | MX | 模型校准 | 用本发次测量数据更新下发次预测模型 |

#### 真空仿真细节（ZK）

抽真空采用 40 步随机指数衰减，确保即使在最差随机情况下也能在阈值内收敛：

```
初始压强：1.013×10⁵ Pa（大气压）
每步因子：random.uniform(0.2, 0.5)
40 步后最差情况：0.5^40 × 1.013×10⁵ ≈ 9×10⁻⁸ Pa  远低于 10⁻³ Pa
```

后台监控以 5s/sim_speed 周期检查，0.5% 概率模拟漏气并发出 S3。

## 4. 集中管控设计

### 4.1 状态机

JZGK 控制器以形式化状态机建模：

```
IDLE ──START──► PREPARING ──A完成──► FIRING ──B完成──► POST ──C完成──► IDLE
  ▲                │                   │                 │
  │                └───────────────────┴─────────────────┘
  │                            任意状态
  └──────────────────────────────────────── EMERGENCY_STOP ─┘
```

**合法转换表**（`_VALID_TRANSITIONS`）：

```python
_VALID_TRANSITIONS = frozenset({
    (IDLE,           PREPARING),
    (PREPARING,      FIRING),
    (FIRING,         POST),
    (POST,           IDLE),
    (EMERGENCY_STOP, IDLE),
    # 任意 → EMERGENCY_STOP（通配，单独允许）
})
```

`_set_state()` 在转换前校验合法性，非法转换立即抛 `RuntimeError`。

**Entry Actions 表驱动**：进入某状态时自动执行副作用，解耦调用方与状态行为：

```python
_ENTRY_ACTIONS = {
    JZGKState.EMERGENCY_STOP: JZGK._safe_state_all,
}
```

进入 `EMERGENCY_STOP` 时，状态机自动调用 `_safe_state_all()`，无需调用方手动触发。

**ShotRecipe**（输入配方）：


**ShotRecord**（执行记录）：

```python
@dataclass
```

**B 阶段硬故障**：BB 充电故障、KG 充电故障。

### 4.5 S3 真空告警决策

S3 告警触发后，按气压量级决策：

```python
if pressure > VACUUM_THRESHOLD * 100:   # 严重泄漏（>0.1 Pa）
    raise ShotAborted(SUBSYSTEM_FAULT, "S3 严重真空泄漏...")
else:
    logger.warning("S3 轻度告警，继续执行")   # 轻度（0.001~0.1 Pa）
```

### 4.6 中止补偿（_safe_state_all）

中止发次时，状态机进入 `EMERGENCY_STOP` 并自动触发补偿。7 项补偿动作并发执行（`asyncio.gather(return_exceptions=True)`），单项失败不阻塞其他：

| 补偿动作 | 条件 |
|----------|------|
| ZZY / EPJ 禁光 | `_activated` 含该项 OR 模拟器处于 RUNNING/READY 状态 |
| BB 紧急停充 | `BB_CHARGED` 在 `_activated` 中 |
| KG 复位 | 模拟器处于充电/就绪状态 |
| JZT 复位 | 无条件 |
| AQ 释放联锁 | 无条件 |
| ZK 停止监控 | 无条件 |

`_activated` 状态检查与模拟器状态检查双重保障，覆盖步骤被取消导致 `_activated` 未更新的边界场景。

## 5. 工作流引擎

### 5.1 设计动机

`_phase_a/b/c` 的原始实现（`asyncio.gather` + 顺序 `await`）存在三个问题：

1. **无重试语义**：步骤失败直接中止，无法区分瞬时故障与永久故障
2. **逻辑与编排混合**：并发调度、故障检查、数据记录散落在长函数中
3. **无每步耗时**：只有阶段总耗时，无法定位瓶颈步骤

工作流引擎以 DAG 声明式描述依赖，分离"做什么"与"怎么调度"。

### 5.2 Step 数据结构

```python
@dataclass
class Step:
    name: str
    deps: list[str]                   # 依赖步骤名（空 = 无依赖）
    action: Callable[[], Awaitable]   # 同步或异步，无参数
    retries: int = 0                  # 最大重试次数（不含首次）
    retry_delay: float = 0.0          # 重试前等待（真实秒）
    soft: bool = False                # True → 失败仅 WARNING，不中止
    timeout: float | None = None      # 单次执行超时（真实秒）
```

### 5.3 执行算法

```
completed = {}
pending = all steps

while pending:
    ready = {s ∈ pending | all deps(s) ∈ completed}
    if not ready: raise 死锁

    # 并发执行当前就绪批次（_run_batch）
    batch_results = await _run_batch(ready)

    for r in batch_results:
        if r.success or step.soft:
            completed.add(r.name)
        else:
            raise WorkflowAborted(r.name, r.cause)
```

`_run_batch` 使用 `asyncio.wait(FIRST_COMPLETED)` 逐步收集结果：首个硬故障触发时，立即 `cancel()` 同批其余任务，不等待它们自然结束。

**外部取消处理**：若 `safety.guard()` 取消整个阶段协程，`_run_batch` 捕获 `CancelledError`，cancel 所有内部任务后 re-raise，确保不产生孤儿任务：

```python
except asyncio.CancelledError:
    for t in tasks:
        if not t.done():
            t.cancel()
    await asyncio.gather(*tasks, return_exceptions=True)
    raise
```

### 5.4 重试与超时

`_run_step` 循环执行至多 `retries + 1` 次：

```python
for attempt in range(step.retries + 1):
    try:
        coro = asyncio.wait_for(action(), timeout) if timeout else action()
        await coro
        return StepResult(success=True, attempts=attempt+1, ...)
    except asyncio.TimeoutError:
        last_exc = TimeoutError(f"超时（>{timeout}s）")
    except Exception as exc:
        last_exc = exc
    # 重试前等待
    if attempt < retries and retry_delay > 0:
        await asyncio.sleep(retry_delay)
```

## 6. 安全体系

### 6.1 三级安全信号

| 信号 | 来源 | 处理方式 |
|------|------|----------|
| S1 | AQ（人员入侵） | 立即中止发次，进入 EMERGENCY_STOP |
| S2 | BB（充电故障） | 立即中止发次，进入 EMERGENCY_STOP |
| S3 | ZK（真空泄漏） | 记录警告，由控制器决策（轻度继续，严重中止） |

### 6.2 SafetyWatcher

`SafetyWatcher` 在发次开始时注册到注册表，订阅所有子系统的安全事件：

```python
class SafetyWatcher:
    emergency_event: asyncio.Event   # S1/S2 触发时 set
    warnings: list[SafetyEvent]      # S3 积累
    _last_emergency: SafetyEvent     # 最后一次紧急事件
```

**guard(coro)**：包裹阶段协程，并发等待 `emergency_event`；任一先完成则取消另一个：

```python
task = asyncio.create_task(coro)
emergency_task = asyncio.create_task(emergency_event.wait())
done, pending = await asyncio.wait({task, emergency_task}, return_when=FIRST_COMPLETED)
# 若 emergency 先触发 → cancel task → raise ShotAborted
```

**check()**：在阶段间同步检查点调用，已设置的 emergency_event 立即触发中止。

### 6.3 信号传播路径

```
子系统硬件异常
    → simulator._emit_safety("S1", msg)
        → registry 广播
            → SafetyWatcher._handle()
                → emergency_event.set()
                    → safety.guard() 取消阶段协程
                        → start_shot() 捕获 ShotAborted
                            → _handle_abort()
                                → _set_state(EMERGENCY_STOP)
                                    → entry action: _safe_state_all()
```
