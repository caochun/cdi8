# 分系统状态机建模说明


本次修订多程放大模型，新增其余十个分系统模型。光纤种子源、二倍频宽带激光注入、再生与双程放大三份参考模型保留原有状态和迁移；LD 靶按既有范围不生成。目录共十四份 SCXML 文件。

当前全部模型共用严格的 `componentMetadata` 校验。说明性 `context_policy`、`source_inventory`、`modeling_notes` 已统一放入 `annotations`；动作和确认事件保持运行含义，字段及状态/事件引用错误会直接报错。具体格式见[自定义模型契约](../../../docs/architecture/custom-model-contracts.md)。

## 建模约定

- 表 E 列业务状态作为复合父状态，D 列关键状态作为叶子状态，原文标签逐行对照。每个模型采用单一活动叶状态，以兼容当前工作台快照协议。
- 服务请求、设备完成反馈分离。请求本身不会虚报完成；参数重新下发的请求先撤销旧参数资格。动作失败没有明确安全落点时保持当前物理状态，等待确认后重试。
- 只使用本分系统内部完成反馈。表内跨系统前置条件保留在建模说明中，由流程编排层负责；不引入外部发射结果待确认状态。
- 保留资格/配置失效、通用异常、执行超时、通信异常、关机及恢复路径，保留必要自环。关机不清除已有故障锁存。
- 异常恢复首先确认内部安全处置和物理状态，进入“就绪/复位待机完成”；此后须重新通过功能检查和参数校验，再进入业务动作。正常待机后也重新检查相应资格。发次重新启动仍由流程层人工发起。
- 参考模型中的未上电/离线、上电检查通过、功能检查失败、通用故障等内部子状态用于区分基础能力和业务资格；它们是闭环补充状态，不替代表中关键状态。
- XML 使用稳定且唯一的 state id；componentMetadata 提供父子标签、动作、状态确认、故障代码以及 Excel 行号映射。点击图形节点可定位 XML 中对应 id。

## Java 工作台契约适配（2026-10-24）

- 本目录成为十四类设备模型的唯一源码位置，替换原 `examples/gxlf/scxml/` 四文件；Java 服务和设备模拟器共同打包这些文件。
- 动作元数据统一使用 `request_event`，将原动作请求准入声明落实为实际 SCXML 请求迁移；请求、成功/失败和物理完成反馈继续分开。`function_check` 使用 `function-check.requested`，`abort_reset` 使用 `abort.requested`。
- 参数重新下发请求先回到基础就绪，撤销旧参数事实；不直接保留旧配置结果。多程采用 `collimation` / `enter_shot`，异常恢复后到 `resetReady` 并重新功能检查。
- 当前 `NewChainIT` 通过真实 Java Tango 链路加载十四模型，完成上电/功能检查与十二类参数动作。充电物理完成、吹扫保护、真空复压和联锁锁存需要在后续完整业务测试中补充。
- 整体设施事实和持续条件统一见 [系统定义模型设计](../../../docs/domain/gxlf/process-control/系统定义模型设计.md) 与 [系统模型与发次模型映射验证](../../../docs/domain/gxlf/process-control/系统模型与发次模型映射验证.md)，不向设备模型填入跨系统资格依赖。
